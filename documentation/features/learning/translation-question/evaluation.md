# Lessons Learned

| Lesson | Supporting finding / evidence | Documentation action or disposition |
| --- | --- | --- |
| When dispatching parallel Builders with `isolation: worktree`, ensure all referenced SDD artifacts (Spec, Evaluation) are committed or otherwise present on disk before worktree creation — an uncommitted Spec is invisible to a freshly created worktree even though it's visible in the main tree. | ACH-03 | No repository documentation change proposed; this is an Orchestrator-tooling-sequencing lesson, recorded here for this session's continuation and future similar sessions. |
| Builders exploring via `git log --all` can surface real commits from other branches that were never merged into the working branch; this is not evidence those commits' code exists in the current tree. Always verify a referenced module file actually exists (`ls`/`find`) before trusting an import, especially when a Builder's own research surfaces suspiciously complete, unrequested functionality. | ACH-01 | Recorded here; no repository-wide rule proposed, since this is a one-off hazard of this session's large parallel-builder dispatch rather than a reusable project pattern. |
| When adding a second instance of an existing AgentOS/Agno `Workflow` subclass that mirrors an existing one's step structure, step-executor method names must be unique across workflow classes sharing a registry/runtime — Agno resolves them by bare name at rehydration, not by qualified name. | ACH-02 | No repository documentation change proposed yet; worth a short note in `documentation/rules/ai-layer-rules.md` about unique step-executor naming across sibling workflows if a third AI-graded question kind is ever added. Not made in this session to keep scope bounded to the Spec. |
| Local `uv run pytest`/`uv run poe check:types` invocations in this environment fail importing the full app because `AWS_PROFILE` is set to a profile (`AdministratorAccess-429135885064`) not configured in this sandbox; `env -u AWS_PROFILE` before the command works around it without touching any file. | Encountered repeatedly this session | Not a repository change; environment-specific. Noted here so a continuing session does not re-diagnose it from scratch. |
| When two sibling AgentOS workflows (`EvaluateCodeActivityWorkflow`/`EvaluateTranslationActivityWorkflow`) share the same shape, a later merge that legitimately changes a shared dependency's return type (here, `EvaluateChoiceActivityUseCase.execute` gaining a real `bool` return on `main`) can silently leave one sibling out of sync if it was last hand-edited against a stale baseline. Diffing sibling workflows line-by-line after any merge that touches their shared use case is cheap insurance. | ACH-04 | No repository documentation change proposed; recorded here as a lesson for this feature's own continuation. |
| The original Handoff's CI numbering (CI-01..CI-13 as independently assigned during the first implementation pass) drifted from the Spec document's own `## Automated` CI-01..CI-13 numbering once the Spec was finalized. Always re-check the Spec's own numbering before trusting an Evaluation's internal references, rather than assuming the two stayed in sync. | Discovered while reconciling Progress/Handoff against `spec.md` this pass | Cross-referenced both numbering schemes in the Progress table's note; no Spec change needed since the Spec's numbering is authoritative and was never wrong. |
| A Spec's "Manual, Playwright CLI" check is a different claim from "an automated Playwright test passed." When the named manual tool is unavailable, say so explicitly and name the substitute instrument used, rather than marking the check simply "Passed" — the reader needs to know no interactive exploration or fresh screenshot happened. | ACH-05 | No repository documentation change proposed; recorded here as a general honesty-in-reporting pattern for any future Evaluation that encounters a missing CLI tool named by its own Spec. |
| Starting this repo's real dev stack (needed for any genuine real-browser Playwright run, as opposed to the mocked-BFF automated suite) requires `AWS_PROFILE` unset (same as pytest) **and** `AGENTOS_DATABASE_URL` exported, which is missing from `apps/server/.env.local` in this sandbox. The failure surfaces through uvicorn's structured JSON logger as two content-free `"error.unexpected"` lines with no traceback — a direct `TestClient(app)` lifespan run is the fastest way to get the real exception. | ACH-05 | Not a repository change (developer-local `.env.local` is gitignored and intentionally not touched); recorded here so a continuing session does not re-diagnose this from scratch. |
| Any Playwright test that lets a component using `useSpeechRecognition`/native `SpeechRecognition` mount without first stubbing `window.SpeechRecognition`/`webkitSpeechRecognition` risks crashing headless Chromium outright (no catchable JS error, just "Page crashed") in a sandbox with no audio/microphone stack. Always call a dictation-neutralizing stub (e.g. `installControlledDictation`) before navigating to any page with a dictation-capable widget. Also, `page.addInitScript` only fires on a fresh document load — this repo's `navigateAuthenticatedPage` is a same-document client-side route change, so overriding globals for "no recognizer" scenarios needs a plain `page.evaluate` before navigating, not `addInitScript`. | ACH-05 | No repository documentation change proposed, since `tests/support/native-dictation.ts` already encodes the correct pattern for Mentor's dictation feature; recorded here so the next question kind that adds dictation does not rediscover this independently. |
